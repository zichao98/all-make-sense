Where these intuitions bend

Convolution or correlation?

Libraries skip the kernel flip that signal processing uses. With learned kernels it makes no difference, so everyone says convolution.

Shift-proof only in the middle

Padding treats borders differently, and stride or pooling only line up every s pixels. A 1-pixel shift can change the output.

Clean spikes need clean lines

(1, −2, 1) also amplifies noise. Real signals give small spikes everywhere, not only at kinks.

Can see ≠ does use

The receptive field lists the inputs that can matter. A trained network may lean on its center far more than its edges.

Convolution Sense · 19　　Size rules from Dumoulin & Visin (2016); every other number was computed for this deck.

Four honest caveats. First, deep learning libraries compute cross-correlation: they slide the kernel without flipping it. Dumoulin and Visin note that the two are interchangeable when the kernel is learned, so the field just says convolution. Second, sharing weights makes a convolution respond the same way to a shifted pattern only away from the borders and only for shifts that line up with the stride. Padding, stride and pooling all break perfect shift-equivariance. Third, the kink-detecting kernel is exact for clean piecewise-linear samples. Second differences amplify noise, so real data gives small spikes everywhere and you need smoothing or a threshold. Fourth, the receptive field says which inputs could affect an output. How much each one actually matters depends on the trained weights and is usually concentrated toward the center. Treat it as an upper bound.
