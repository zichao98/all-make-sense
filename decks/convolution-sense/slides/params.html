The kernel sets the cost, not the image

A bigger image only adds positions. That costs compute time, not weights.

Weights in a conv layer:

k = kernel size, m = input maps, n = output maps. Add n biases.

Convolution Sense · 10　　Weights only. Biases add one per output unit (dense) or one per output map (conv).

Here is why sharing matters in practice. A dense layer from a 28×28 image to a 28×28 output connects every input pixel to every output unit: 784 × 784 = 614,656 weights. A single 3×3 kernel producing a same-size map with padding has 9 weights. Take a typical first layer: a 224×224 colour image, 3 channels, mapped to 64 feature maps with 3×3 kernels. That is 3 × 3 × 3 × 64 = 1,728 weights. A dense layer between the same shapes would need 150,528 × 3,211,264, about 4.8 × 10¹¹ weights. The general count for a convolutional layer is k² m n, plus n biases, and the image size does not appear in it. A larger image means more positions, which costs computation but adds no weights.
