One-page takeaway

A kernel is a neuron, copied

One small ReLU neuron at every position: a local window and shared weights.

Kinks ↔ spikes

(1, −2, 1) turns kinks into spikes. Spikes ∗ one ramp rebuild the line: a 1D ReLU layer is already a convolution.

Tied rows, few weights

As a matrix, each row is a fold and all rows share one kernel. The weight count ignores image size.

Count where the kernel fits. Pooling uses the same count.

Depth widens the view

Plain 3-wide layers see 3, 5, 7, 9 inputs. Dilations 1, 2, 4, 8 see 3, 7, 15, 31.

Transposed = C transposed

Same connections, opposite direction. It restores the shape, not the values.

Convolution Sense · 20　　Arithmetic follows Dumoulin & Visin, “A guide to convolution arithmetic for deep learning” (2016).

Back to the question: how does the idea of a kink extend to convolution? A ReLU neuron is one fold. In one dimension, a whole layer of them is one ramp shape slid to many places and scaled, which is a convolution of a spike train with a ramp. The second-difference kernel (1, −2, 1) runs that in reverse and turns every kink into a spike. A convolutional layer keeps the neuron but changes what is learned and where it looks. Each copy sees only a small window, every position gets a copy, and all copies share the same weights. In 2D each output is a fold in the space of 3×3 patches, and in matrix form every row is an ordinary dense neuron with tied weights. From there Dumoulin and Visin's arithmetic is just counting: padding adds room, stride jumps, the floor drops leftovers, pooling counts the same way, dilation and depth widen the view, and the transposed convolution runs the same connections backwards to recover the shape.
