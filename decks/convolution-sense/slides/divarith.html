Part Three

Convolution arithmetic

Output size = the number of places the kernel fits.

Dumoulin and Visin derive every case from this one counting idea. Axes don't interact, so we count along one axis; a square input just repeats the answer.

Now the arithmetic, which is the heart of Dumoulin and Visin's guide. When you design a network, you constantly need to know how big each feature map will be. Their key observation is that every rule comes from counting the positions where the kernel fits. Padding adds room at the edges. Stride makes the kernel jump. Pooling uses the same count with a different function. Transposed convolution reverses the shapes. Each axis is independent, so we can think along one axis at a time.
