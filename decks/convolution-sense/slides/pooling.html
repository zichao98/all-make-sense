12 · Pooling

Pooling counts the same way, with max

Same count, no padding. Here a 6×6 map becomes 3×3.

The window and stride work as before. Only the function changes: max (or average) instead of a weighted sum.

Max is folds too:

A 2×2 max = 3 kinks, no weights

Max of 4 numbers = max of two maxes. Pooling adds fixed folds and shrinks the map.

Convolution Sense · 16

Pooling slides a window just like a convolution, but instead of a weighted sum it applies a fixed function, usually the maximum or the average. The guide points out that the counting argument never used the sum, so the same rule holds: o = floor((i − k)/s) + 1, with no padding in the usual setup. The animation uses the most common choice, 2×2 windows with stride 2, on a 6×6 map I made up for this slide: floor((6 − 2)/2) + 1 = 3, so the output is 3×3, and the windows don't overlap. Here is the link back to kinks. The maximum of two numbers is a plus ReLU(b − a): one fold. The maximum of four numbers is the max of two maxes, so 3 folds. Max pooling therefore adds a few fixed kinks with no trainable weights. In the backward pass, only the winning input gets the gradient. The guide describes pooling as giving some invariance to small translations, because a feature that moves inside its window gives the same maximum.
