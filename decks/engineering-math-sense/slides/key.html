So the useful question changes

“Why won’t it train?”
= “Which math is failing?”

Frameworks change every year; the math underneath does not. Learn what each branch does, and a symptom points you to the right chapter.

This is the thesis of the article and of this deck. Tuning tricks go out of date with each new framework or model family. The underlying structures, matrices, gradients, distributions, finite-precision arithmetic, iteration, do not. The article's advice is that real progress is not memorizing more tricks but being able to look at an engineering symptom, such as a loss that oscillates or a NaN that appears, and say which kind of math problem it is. The deck is built to give you that reflex: first the three translations every problem goes through, then one picture per branch of math, then a symptom map with worked numbers.
